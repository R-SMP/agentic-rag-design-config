OpenSCAD models

A parametric OpenSCAD model can be a configurator's tool: the engine runs the model, with no code written for it.

Import a model

Drop an OpenSCAD model (.scad) on the Tools page, or use Import a .scad file (or New tool › A CAD file). The Studio reads the settings the model's own Customizer shows — the plain values set above its first module or function, in its /* [Tab] */ tabs — and shows what each one becomes before anything is written:

  • a parameter the agents set: a number, a drop-down (a choice), an on/off setting. A drop-down of evenly spaced numbers becomes a number; a pair written as [mm, inch] becomes one millimetre parameter; another list of numbers becomes one parameter per number (_x, _y, _z);
  • the model's detail (fa, fs, fn): its own values for the Download buttons, coarser ones for the agents' runs, which are quicker;
  • left to the model: text, colours and other lists, and the tab "other": the model keeps its own value. You can leave any setting to the model.

A setting of a tab named like Connector 1 - Flange is proposed as used only when a choice of the tab Connector 1 has the matching value (here: the flange style); untick it if that is wrong.

Two ways to import

  • Start a new configurator: the model's parameters replace the setup's, every agent's parameter list is written new, the setup's generator and geometry tools are replaced by the model (a generator, and a geometry tool for the Download buttons), the setup's browser preview goes (it draws the old model; the Parameters page's Preview button builds the new one on the server), and the picture samples become one, the defaults. The setup's texts stay as they were: rewrite them for the new model (its name, what it is, its examples). No agent gets the primer until you give it the new model's picture and text, on the Primer page.
  • Add it as one more tool: its parameters join the setup's (a name the setup already has is refused); it becomes the generator if the setup has none, otherwise a geometry tool.

Undo the import (in the banner on the Tools and Parameters pages) puts back every file it touched, as long as it can be undone; it names first anything you changed since.

Review the ranges

A model rarely says how far a number may go. Where it does not, the import proposes a range from the model's default — half to double it, or 0 to ten steps from 0 — and shows it in amber under Parameters. Set the real range (editing min or max ends the proposal), or keep it as it is (Keep this range, or Keep all … in this group). Only ranges to review shows just those; Validate warns while any is left.

The manifest

An imported tool's tool.yaml names the model instead of code; you can also write one by hand:

backend: openscad
model: my-adapter.scad             # in the tool's folder
parts:                             # one setting of the model made of parameters
  End1_Diameter: [End1_Diameter_mm, 0]
fixed: {Enable_Help: false}        # settings the agents never change
detail:                            # per purpose
  agent: {fa: 6, fs: 1}
  download: {fa: 3, fs: 0.1}
timeout: 120                       # seconds

Every parameter goes to the model's setting of the same name; every other setting keeps the model's own value. The model's STL becomes the attempt's model file, and a generator's pictures come from the engine's renderer.

OpenSCAD on your computer and on the deployment

  • Install OpenSCAD (openscad.org) and put it on the PATH, or set OPENSCAD_PATH to the program or its folder. Without it, Test tool and Validate say so.
  • Recent models may need a recent OpenSCAD: the 2021.01 release cannot read some of them. A downloaded package's image installs OpenSCAD 2026.10.18, a development snapshot pinned by its checksum (the version the vacuum hose adapter was built with), on an x86-64 machine such as Railway's. So does this repository's image, for the vacuum hose adapter.
  • A model has its own licence: check that it allows what you do with it — some authors ask that their script not be hosted or uploaded anywhere.
