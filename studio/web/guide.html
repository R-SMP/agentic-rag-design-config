Getting started

The MAS Studio turns this multi-agent system into one for your own design configurator.

What it is

A design configurator is a parametric model: a set of numbers, its parameters, that a tool turns into a 3D model and pictures. The agents take a design request in plain words (and sketches), choose the parameters, build the design with the configurator's tools, check it and explain it.

Everything that belongs to one configurator is its setup, the dc_pack/ folder: its parameters, the texts the agents read about it, and its tools. The Studio edits the setup; the engine that runs the agents stays the same.

1. Open the Studio

  • Online: open the Studio's address and type its access code; this browser remembers it. The first page offers Open the Studio, Import a setup and Start again from the example.
  • On your own computer: in the repository's folder, run python -m studio and open http://127.0.0.1:8770/.

You start from the example setup, the propeller configurator: change it into yours.

2. Make the setup yours

The left column lists the setup's sections in the order to work through them:

  1. Identity: the configurator's name and how the agents introduce it.
  2. Parameters: each parameter's name, type (whole number or decimal), range, step, default, group, label and unit. Import JSON and Paste CSV bring a whole list in. The agents' parameter lists follow by themselves.
  3. Configurator description: what it builds, how its parameters behave, what it can and cannot do: the longer texts the agents read.
  4. Outputs & vocabulary: the words for what it produces (its model, its pictures).
  5. Tools: how a design gets built. New tool starts one from a template (a helper, a generator, a geometry tool) or as a copy of a tool; then change its code and its manifest (tool.yaml). Test tool runs it on the parameters' defaults and shows what it answers, its pictures and its model.
  6. Examples: short phrases quoted inside the agents' instructions. Keep each on one line, in its shape.
  7. User input types: how the agents treat a sketch or a reference picture.
  8. Agent access: which agent sees the parameter list, with or without the ranges.
  9. Settings & secrets: the tools' settings, and the variables (keys) they need. The values go in .env or in the deployment's variables, never in the setup.

Each field saves on its own, and Undo puts it back as it was when the Studio opened. A field shows its text for the 3-, 5- and 7-agent teams; the link icon makes it one text for all of them, or one per team.

The Prompt viewer shows every agent's full instructions as the engine builds them, coloured by where each part comes from; Changes since opened shows what your edits changed.

3. Validate

Press Validate in the toolbar. In about a minute it checks that the setup loads, that every agent's instructions build, that the parameter lists match, that each tool runs and makes what it declares, and that a turn goes through with a stand-in model (no cost). Fix every failure: a line that names a file opens it. A warning does not stop the setup working: text left about a tool you removed, or something this computer lacks (a package, a program) that the deployment has.

4. Save your work

Download setup file gives the setup alone; Open setup file (online: Import a setup) brings it back, in place of the open setup. Online, everyone with the access code shares one setup, and it goes back to the example when the Studio restarts: download it to keep your work.

5. Deploy it

  1. Download full package: the engine and your setup, in one folder.
  2. On your computer, in that folder, run python -m studio prepare. It checks the folder (Validate, what git must leave out, anything that looks like a key) and prints the git commands; it never runs them.
  3. Run those commands: they make a private GitHub repository with your system.
  4. Follow DEPLOY.md: a Railway service from that repository, with your access code and an OpenAI key.

To change it later: python -m studio in that folder, Validate, then commit and push; Railway deploys the new version.

6. What it cannot do yet

  • A tool is Python code. The Studio does not yet connect an OpenSCAD model, a Grasshopper definition on a compute server, a Node script or a web service by itself, nor turn a CAD file into a tool.
  • Online, the shared setup is not kept across a restart.
